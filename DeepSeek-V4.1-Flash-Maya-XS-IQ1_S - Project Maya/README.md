# DeepSeek-V4.1-Flash-1017 (Maya-XS IQ1_S) on Project Maya — the bench record on box .5

**2 recorded runs (6 measured arms), 0 failed.** DeepSeek-V4.1-Flash-1017 served by
Project Maya **v1.1.22** (engine `maya-ds4`) on **2× Tesla V100 32 GB**, measured **2026-10-22** on
box .5. One GGUF set: Maya-XS IQ1_S, **276.6 GB** across five shards, layer-split across both cards,
**131,072 context**, no speculation. Every number came off a real run on this hardware.

The findings that matter:

- **Prefill 255 / 340 / 378 tok/s** at 20K / 60K / 100K (means), **peak 383.7 tok/s**; **decode
  14.1 / 16.3 / 17.3 tok/s**, peak 20.9. Both climb with depth as the expert caches warm.
- **2.20× prefill and 2.49× decode against the Maya-S run two days earlier** (mean of depth means,
  147.8 → 324.5 and 6.37 → 15.87 tok/s). The delta spans **two** changes — the quant
  (IQ2_XXS → IQ1_S) and the engine (v1.1.19 → v1.1.22) — and is **not** a tensor-parallel win: TP
  was refused on both sides (below).
- **Why XS is faster: residency.** XS puts 7,432 of 15,360 routed experts in VRAM (48%) against
  4,651 (30%) for Maya-S, so the CPU lane carries 54.8 GB read in place instead of 117.8 GB.
- **Tensor parallel is impossible on these quants on two GPUs.** The config asks for `--tp 2`; the
  engine reduces it to 1 at every start because 2,304-wide expert blocks do not halve into whole
  256-value blocks. Only 1, 3 or 9 parts divide 2304 cleanly. Both cards are still used — one layer
  group each.
- **Decode spread between loads is 31–98%** on this engine: the load warmed by the burn battery holds
  19.9–20.9 tok/s; the fresh load starts at 7.2 and climbs to 14.6. The two-run mean is the published
  figure; the warm-only number is the top of the range. The burn battery reads 7.6 / 15.4 / 17.7 —
  the same shape.
- Runs recorded: **2 — both measured, 0 failed.** All six arms completed 400 tokens and both runs
  sliced the same document at each depth. The 19:11Z burn battery is excluded by design.
- Maya-S was not re-run for this comparison: its quant had been deleted before the update, so the
  pair is today's XS against the archived 21 Oct runs (same harness, same battery, same box).

## Model and layout on the box

- `peasantsmith/DeepSeek-V4.1-Flash-1017-Maya-GGUF` @ `c273fcb`, `Maya-XS/` — 5 shards, **276.6 GB**
  (weights 115.3 GB in shards 1–3; Engram Q6_K 161.3 GB in shards 4–5), plus Maya-XS's own 2-bit
  DSpark drafter `dspark-xs2` (4.25 GB) — downloaded, not used.
- Weights on the SN730 NVMe (`/mnt/nvme/maya-ds4/Maya-XS/`), Engram shards on the boot SATA SSD
  (`/home/eamon/maya-ds4/engram-xs/`, symlinked into the model dir). Pack is an index only
  (`tensors.txt` 3.6 MB, `engram.bin` 518 KB) plus the engine's `expert-profile.bin`.
- Engine: 7,928 routed experts on the CPU lane (54.8 GB, read in place), 14 threads; CUDA0 3,729 of
  7,680 + CUDA1 3,703 of 7,680 in VRAM; ~580 MiB free per card. Load ~45 s.
- Speed calibration at setup: **13.9 tok/s without drafting vs 11.7 tok/s with the XS drafter**
  (68% of drafts accepted) → the config keeps `--dspark none`.
