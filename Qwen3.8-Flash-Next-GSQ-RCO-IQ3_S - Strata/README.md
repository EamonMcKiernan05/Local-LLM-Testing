# Qwen3.8-Flash-Next IQ3_S on Strata — every measurement we took

**231 recorded runs on Qwen3.8-Flash-Next (125B MoE, ~6B active) served by Strata on 2× Tesla
V100 32 GB — measured 2026-10-03 to 2026-10-07 on the box brought up 2026-09-30.** One GGUF set
throughout: the base `IQ3_S` (GSQ-RCO, 54.8 + 28.8 GB) on both cards. Every number came off a
real run on this hardware; nothing is estimated from a datasheet.

The findings that matter:

- **Deep-context speed barely decays.** On v0.1.40.2: decode **70.3 tok/s at 20K** prompt depth →
  **63.0 at 250K**; prefill 1,384 → **2,110 tok/s peak** (100K) → 1,936 at 250K. The full 256K
  window runs on both cards (~30.7 / 31.5 GB VRAM in use at 250K depth).
- **The v0.1.39 release is a big one: +26.9 % decode, +21.5 % prefill** on an identical battery,
  same day, same config — only the engine differs (experiment 06).
- **The v0.1.40.1 update adds +5.9 % prefill** on a day-matched battery — the win is the retired
  sm_70 prompt-kernel workaround the box had been forcing (engine-to-engine the release is
  ~neutral); decode moves within single-rep noise (experiment 08).
- **The v0.1.40.2 update is parity on this box**: prefill +0.4 % mean, decode within the ±5–8 %
  single-rep band (experiment 09). Its fixes target other setups — 3–4 GPU splits, low-RAM
  streaming, Intel Arc; here both expert caches are already resident.
- **`STRATA_PREFILL_CPU_SHARE=auto` can't engage on this box** — it is a single-GPU feature
  (the CPU pool is wired to prefill only in non-split runs), and the measurements agree: short
  prompts +0.6 % mean, battery ±1 % (experiment 10).
- **The storage rule is the biggest lever the box has.** Strata's n-gram table is read randomly
  per token; it must live on the NVMe. This is the origin of the box's storage policy
  (experiment 01, `HARDWARE.md`).
- **The drafter gate is the knob that matters, and it needs a full sweep.** 126 runs at six
  depths: `--spec-min-p 0.50` wins on the mean (56.8 tok/s vs 53.3–53.7); the single-run "0.85
  at 100k" story did not generalise. Suffix-draft default 3 and coupled-draft off are both
  confirmed; the sampler trims are flat — no llama.cpp-style `top_k` trap (experiment 05).
- **Vision works on the V100s.** Images read correctly on GPU (4.0 s, 93 tok/s decode); text
  prefill pays ~4.5 % for the VRAM reserve (experiment 07).
- Runs recorded: **231 — all 231 with measurements** (warm-ups were discarded by design; a few
  rows are annotated warm-up/cold — see `PROVENANCE.md`).

## Method, and what is deliberately not claimed

- **Measurement source is stated per table.** Sweep figures come from each response's `timings`
  plus the engine's per-request log; the batteries come from the model-bench harness (server
  timings). Acceptance figures are per-request (drafts accepted / proposed in the measured
  request), not cumulative counters.
- **One measured run per arm, unique documents, a discarded warm-up** unless a table says
  otherwise. Single cells at depth carry ±5–8 % run-to-run noise; claims that matter are ranked
  on means across depths, and the one pattern that is NOT claimed as real is the per-cell "gate
  flips with depth" reading (experiment 05).
- **The only derived numbers** are the acceptance percentages, the release deltas and the sweep
  summary means/bands — formulas in `PROVENANCE.md`.
- **The hero run has a counting nuance worth knowing:** the raw JSONL holds the client's view
  (document length, stream span, event count) and the engine line holds the request's counts
  (250,632 prompt tokens; 6,000 generated). Both are recorded; the card uses the engine's
  numbers (experiment 04).
- **The suffix-draft results carry a caveat:** the sweep's source document is highly repetitive,
  which flatters prompt-lookup drafting vs ordinary text.

## Reproducing

The config every benchmark ran on is on the box at `~/Strata/strata-iq3_s.json`; the full flag
set is quoted in [`HARDWARE.md`](HARDWARE.md). A measurement is one HTTP call:

```bash
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3.8-flash-next-iq3_s",
       "messages":[{"role":"user","content":"[unique-tag] Your prompt here"}],
       "max_tokens":400,"temperature":0.5,"seed":12345,
       "strata_tune":{"spec_min_p":0.5}}' | python3 -c \
  'import json,sys; print(json.load(sys.stdin)["timings"])'
```

Give every request a unique first line (an identical prompt is a cache hit, not a
measurement), and discard the first request after any load.

## What we still cannot answer

- **No repeats at most depths.** One run per arm; the ±5–8 % band is estimated from the cells
  that were repeated.
- **The gate's per-depth behaviour is only settled on the mean.** If you need a per-cell claim,
  re-run that cell several times.
- **Vision was verified with one test image and text spot-checks**, not a formal battery.
- **No other quants were measured** — this repo is IQ3_S only.
- **The 0.1.40.1 comparison is one battery per side.** The 60K–250K prefill gains are consistent
  across all six depths; the decode deltas are single-rep noise (experiment 08). The 0.1.40.2
  comparison is likewise one battery per side — a parity read (experiment 09).
- **The CPU-share feature is only tested out of its lane here.** It cannot engage on a layer
  split, so nothing here says how it behaves on the single-GPU boxes it was built for
  (experiment 10).
