# 08 — v0.1.39 → v0.1.40.1: day-matched battery, and the sm_70 workaround retired (2026-10-07)

The second update cycle on this box, again a clean before/after: same model, same six-document
battery, same day. The 0.1.39 side was re-run fresh with the start config it had been serving
with — including `STRATA_PROMPT_ATTN_OLD=1` (the workaround below) — so both sides are same-day
and method-identical. The fresh run landed within ~1 % of the archived 2026-10-04 numbers at
60K–250K (20K: +5.2 %, the noisiest cell).

Two things changed at once on the box, and this experiment measures them together:

- **The engine** — 0.1.40 plus the 0.1.40.1 server-only fixes (a quoted `<tool_call>` no longer
  fires; requests waiting through an engine restart no longer hang).
- **A retired workaround** — this box had forced the old prompt-attention kernel since the
  0.1.31/0.1.32 trap (upstream #371). Upstream fixed the guard in 0.1.33, and sm_70 now takes its
  own default kernel (`launch70`, m8n8k4). A warm A/B on 0.1.40.1 (8K and 100K prompts, forced
  old kernel vs default) measured +5.0 % / +6.8 % prefill for the default — the same size as the
  battery gain below, so the update's prefill win is that kernel change, not new engine code.

experiment 06 saw +3.6 % the other way). The decode mean sits inside the ±5–8 % single-rep band;
do not read it as a claim.

## Update procedure (same shape as experiment 06, one new trap)

1. Stop the engine (`kill -TERM <serve/server.py pid>`); verify VRAM drops.
2. `git fetch origin --tags --force && git checkout v0.1.40.1` — the `--force` is needed once:
   upstream rewrote the repo history on 2026-10-06, so a plain fetch/pull refuses and stale tags
   point at the old history.
3. `STRATA_EXPERIMENTAL_SM60=1 ./setup.sh --update` — engine + vision encoder rebuilt (~75 s with
   ccache warm), configs byte-identical, server not started.
4. Start with `STRATA_EXPERIMENTAL_SM60=1` only (`~/strata-start.sh`) — the workaround is gone.
