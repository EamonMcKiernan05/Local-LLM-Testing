# 10 — CPU-share test: short prompts + battery control (2026-10-07)

`STRATA_PREFILL_CPU_SHARE=auto` (0.1.40.2): for prompt chunks under 1,024 tokens it hands the
idle decode CPU pool the non-resident experts few of the chunk's tokens route to. Upstream
measures −19–35 % prompt time on 512–1,000-token prompts on single-GPU boxes; the output drifts
in the last bits, so it ships off by default.

Tested as asked, on box .5: 512 / 1,000 / 2,000 / 4,000-token prompts (exact slices of one
document), 3 reps per size per arm, median of 3; two server sessions (off = default env; auto =
`STRATA_PREFILL_CPU_SHARE=auto`), identical prompts both arms, warm-up discarded. Plus the
standard six-depth battery as a control on the auto arm.

**Result: no effect anywhere** — short prompts +0.6 % mean (all four sizes inside ±1.2 %, run
noise), battery ±1 %.

**Why (source-verified):** the feature cannot engage on this box. `Prefill::set_cpu_pool` is
called only in non-split runs (`!multi_gpu` — src/program/generate.cpp), and this box runs a
two-GPU layer split — so the CPU pool is never wired into the prefill path
(`cpu_pool_ == nullptr`) and the share logic is dead code here. That matches upstream's
"Serve without `--batch`, one GPU." Nothing measured here speaks to the feature on a single-GPU
box; it shows the layer-split config is out of its scope.
