# 06 — v0.1.32 → v0.1.39: same battery, same day, one engine changed (2026-10-04)

The first update cycle on this box, done as a clean before/after: same model, same config, same
six-document battery, same day — **only the engine differs.** Both sides were measured with the
model-bench harness; the 0.1.32 side was deliberately re-run first so the comparison is
method-identical (it landed within noise of the earlier depth card, e.g. decode 56.6 vs 58.1 at
20K).

The update procedure that worked (and the traps that make it non-obvious):

1. **Stop the engine first.** While the binary is running, `setup.sh --update` skips the rebuild
   ("engine ... in use") and the copy onto the live binary fails `ETXTBSY`.
2. `cd ~/Strata && git fetch --tags && git checkout v0.1.39` — checkout the **tag**, not main.
3. `export STRATA_EXPERIMENTAL_SM60=1 && ./setup.sh --update` — rebuilds only what changed
   (~45 s incremental here), refreshes packages and draft subsets, never starts the model.
4. Verify `engine-cuda12/BUILD.json` shows `"version": "0.1.39"`, and that every model config is
   byte-identical to its pre-update snapshot (both were). Then start with the two sm_70 env
   flags around `run-iq3_s.sh`.

## Results (base IQ3_S, 2×V100, ctx 262144, int8 KV, gate 0.50, temp 0.5, seed 12345, 400 gen, six unique documents)

|---|---|---|---|---|---|---|
| 20K | 56.6 | 73.9 | +30.6 % | 1,240.6 | 1,285.7 | +3.6 % |
| 60K | 51.9 | 63.2 | +21.8 % | 1,555.4 | 1,912.7 | +23.0 % |
| 100K | 52.1 | 65.5 | +25.7 % | 1,568.9 | 1,973.0 | +25.8 % |
| 150K | 48.8 | 64.0 | +31.1 % | 1,550.7 | 1,946.4 | +25.5 % |
| 200K | 49.0 | 60.3 | +23.1 % | 1,505.5 | 1,884.1 | +25.1 % |
| 250K | 50.3 | 65.0 | +29.2 % | 1,449.6 | 1,822.6 | +25.7 % |
| mean | | | **+26.9 %** | | | **+21.5 %** |

Reading: the decode gain (+22–31 %) is upstream #646 — fewer launches / host round-trips per
verify pass (upstream didn't measure big-VRAM cards; here the expert caches are ~fully
resident). The prefill gain from 60K up (+23–26 %) is #583's byte-sized streamed ring plus
`--prefill auto` chunking, which pay off when there is free VRAM. The 20K prefill barely moves
(+3.6 %) — matching upstream's "short prompts keep the old ring".
