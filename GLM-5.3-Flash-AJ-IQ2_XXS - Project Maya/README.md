# GLM-5.3-Flash (AJ-IQ2_XXS) on Project Maya — the bench record on box .5

**87 recorded runs on GLM-5.3-Flash (321B MoE, ~18B active) served by Project Maya on 2× Tesla
V100 32 GB — measured 2026-10-16 (engine v1.1.13) and 2026-10-17 (the v1.1.13 → v1.1.15 pair + a
DFlash2 drafting test) on the box brought up 2026-09-30.** One GGUF set throughout:
aj9o9's AJ-IQ2_XXS mix (87.35 GB, two shards, 2.23 bpw, no MTP block), layer-split across both
cards, benched at the full **262,144 context** (six depths) and at **131,072** (the three shared
depths). Every number came off a real run on this hardware; nothing is estimated from a datasheet.

The findings that matter:

- **Engine v1.1.15 is +9.0 % prefill over v1.1.13 on this quant** (+7.6…+10.3 % at every depth,
  alternated 3+3 pair, identical config); decode is unchanged within the box's session drift. The
  applicable change is the V100 two-pass prompt attention (#196). The 256K card below carries the
  v1.1.15 numbers; the v1.1.13 numbers are the 2026-10-16 record (re-measured within 1 % on the
  17th, which is what makes the pair a version effect).
- **DFlash2 drafting is slower on this box: 23.8 → 16.9 tok/s decode mean (−29 %)**, at every
  depth, against no drafting at all (three fresh-load runs per side, same six depths). Maya's own
  first-start calibration (DFlash2 19.6 vs 23.6 tok/s at 8K) agreed before the bench.
- **Depth profile (v1.1.15): prefill climbs 714 → 870 tok/s from 20K to 200K, settling at 851 at
  250K; decode sits at 22.5–24.9 tok/s across all six depths.** On v1.1.13 the same battery read
  652 → 801 and 22.3–24.8. At 131K (v1.1.13) the shared depths read 653 → 761 tok/s prefill and
  24.1–25.4 decode.
- **No speculative drafting — the quant ships without its MTP block.** Zero `glm mtp` markers on
  every engine load, `draft_n: 0` on every measured arm: the numbers are raw single-pass decode
  (four independent checks in experiment 01).
- **Context length is free on this box: 131K vs 256K is parity** — decode +2.6 % mean, prefill
  +0.3 % mean at the shared depths (20K / 60K / 100K), same day, same file, same rig, three runs
  per side.
- **Three-run spreads are tight:** sd ≤ 3.8 tok/s on prefill (≤ 0.5 %) and ≤ 0.76 tok/s on decode
  across every depth — means are quotable; single cells in other datasets still carry the usual
  ±5–8 % class, so read the means and the shapes, not the third significant figure.
- **Cross-check against Maya-S (observation, not a controlled pair):** same SN730 storage, Maya-S
  *with* MTP drafting read 594–647 tok/s prefill / 20.1–23.1 decode at 20K–60K on 2026-10-15 (64K
  config); AJ *without* drafting reads 652–705 / 23.3–24.8 at the same depths (256K config).
  Different days and configs — a controlled no-draft-vs-draft follow-up is the thing that would
  settle it.
- Runs recorded: **33 — all 33 measured, 0 failed**; the post-copy burn battery (6 arms) is
  excluded from the means by design (house method; it read 0.2–1.2 % under the measured batteries).
  7 warm-up requests discarded by design.

## Method, and what is deliberately not claimed

- **Three fresh-load runs per depth per config**: one engine load per battery, a discarded warm-up
  request, the mean of the three measured values. The discarded post-copy burn battery sits in the
  records (`side` = "256K ctx (burn, excluded)") and is excluded from the means by design.
- **Same prompts, provably**: the battery slices the same corpus document per fixed depth on every
  run (frankenstein / sherlock / pride / tale2cities / greatexp / mobydick, exact-token with the
  pack tokenizer); the data builders assert the book and `sliced_tokens` match at every depth —
  across every battery in their table — before they write anything. `ptok` jitters ±1–2 from the
  per-request unique tag (spread ≤ 2 here).
- **Pairs alternate**: an engine/config comparison runs its arms alternating sides (O N O N O N),
  one fresh load per battery, so the first-position edge a single-ordered pair carries cancels.
  Both sides of a pair are measured the same day, from the same quant set and the same config
  bytes (md5-gated); an archived number is only used as a reproducibility check, never as the
  comparison side.
- **Gates on every arm**: `n_ctx` asserted (262144 / 131072), engine `src` stamp asserted
  (`c823b8ca185405dd` = v1.1.13), the configs md5-gated on every start; the engine log shows
  `glm mtp=0 glm dflash=0` markers per battery.
- **Every derived number is the per-depth delta** — `100 × (131K / 256K − 1)` on the unrounded
  means — and appears in `data/csv/ctx-deltas-aj-256k-vs-131k.csv` before it appears on a chart.
- **Not claimed:** nothing about drafting-on vs drafting-off (no controlled pair was run — the
  cross-check above is an observation); nothing about other GLM-5.3-Flash quants; nothing about
  vision (images were enabled in the config, but this bench is text-only).

## Reproducing

The configs the two sides ran on are `data/raw/config-256k-served.json` and
`data/raw/config-131k-served.json` (on the box: `~/project-maya/maya-aj-iq2_xxs.json`, the two
differing only in `--max-context`). A measurement is one HTTP call through the model-bench
harness on box .5:

```bash
cd ~/model-bench
export MODEL_BENCH_GGUF="/mnt/models/GLM-5.3-Flash-AJ-IQ2_XXS-GGUF/GLM-5.3-Flash-AJ-IQ2_XXS-00001-of-00002.gguf"
export MODEL_BENCH_PACK="/mnt/models/GLM-5.3-Flash-AJ-IQ2_XXS-GGUF/pack/tokenizer"
/home/eamon/Strata/.venv/bin/python bench.py --url http://127.0.0.1:8080 \
  --label <label>                     # 256K cycle: the six standard depths
/home/eamon/Strata/.venv/bin/python bench.py --url http://127.0.0.1:8080 \
  --label <label> --depths 20k,60k,100k   # 131K cycle: the shared depths
```

Give every request a unique first line (an identical prompt is a cache hit, not a measurement),
and discard the first request after any load. The whole cycle is scripted in
`data/raw/driver-aj-256k-cycle.sh` and `data/raw/driver-aj-131k-cycle.sh`. The three cards
regenerate from `data/csv/` with the `scripts/` chart scripts (any Python with matplotlib; the
house render venv lives gitignored in the Maya-S folder's `charts/.venv`).

## What we still cannot answer

- **No controlled drafting comparison.** AJ (no MTP block) vs Maya-S (MTP drafting) ran on
  different days, configs and depths — the comparison above is an observation, and the headroom
  drafting might add on this file is unmeasured.
- **One quant only** — aj9o9's AJ-IQ2_XXS mix; nothing here generalises to other AJ or community
  GLM-5.3-Flash quants.
- **The 131K comparison is three cells per side** — enough to say "parity, no measurable cost";
  not enough to defend the +2.6 % decode reading as a real gain.
- **Storage is the known cap** on this box (the expert tiers stream off the SN730); the engine's
  own counters under `data/raw/engine-stats-*.txt` are the evidence to reach for if a later run
  reads slow.
