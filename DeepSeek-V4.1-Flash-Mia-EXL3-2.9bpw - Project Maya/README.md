# DeepSeek-V4.1-Flash-1017 (Mia-AiLab EXL3 2.9 bpw) on Project Maya — the bench record on box .5

**4 recorded runs (12 measured arms), 0 failed.** DeepSeek-V4.1-Flash-1017 served by Project Maya
**v1.1.53** (engine `maya-ds4`) on **2× Tesla V100 32 GB**, measured **2026-11-05** on box .5, from the
NVMe copy. One set: **Mia-AiLab `DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw`** @ `45ee5d0f` — 210.7 GB
of trellis weights in 39 shards plus DeepSeek's **203.1 GB FP8 Engram** pair (`model-00047/48-of-00048` @
`1bae0e10`), 413.7 GB total, 386 GiB on disk — at **131,072 context**. Every number came off a real run.

The findings that matter:

- **Prefill 176.8 / 297.0 / 343.6 tok/s** at 20K / 60K / 100K (2-run means, drafting off), **peak 349.7**;
  **decode 5.50 / 6.25 / 5.90 tok/s**, peak 6.5.
- **About half the speed of the unsloth IQ1_S set on the same box, same prompts, same day**: it reads
  prompts at **2.01×** and writes at **2.72×** the IQ1_S time per token at 100K depth (i.e. IQ1_S is
  2.01× and 2.72× faster). Card and per-depth CSV:
  `charts/ds4-udiq1s-vs-mia-exl3-128k-v100.png`.
- **This is the quant where tensor parallel actually engages on two V100s.** EXL3's trellis tiles are
  128 wide, where IQ1_S expert blocks are 256, so 2304/2 divides cleanly: the calibration reports
  `--tp 2 requested, effective TP per GPU: 2/2` here, against `1/1` for the GGUF set. Measured gain from
  real TP: 4.6 against 4.1 tok/s and 186 against 129 tok/s on a 15,671-token prompt.
- **Real TP does not rescue it.** The set is a bigger expert matrix at 2.9 bpw: the CPU lane carries
  11,525 experts — **148.0 GB read in place** — against IQ1_S's 8,918 experts / 67.1 GB, even though EXL3
  keeps slightly more experts resident (7,670 against 6,448 of 15,360).
- **DSpark loses here too**: 3.32 tok/s with it against 4.96 without (566 of 843 drafts accepted) — the
  calibration kept `--dspark none`. Prompt-lookup drafting (`--suffix-draft 3`) is a wash: +1.7 % prefill
  and +0.8 % decode at 100K, −10.0 % decode at 20K.
- **sm_70 runs the legacy EXL3 kernels**: the engine logs `exl3: CUDA0/CUDA1 decodes with v1.1.8's
  kernels`. EXL3 is admitted from V100 up on current trees (`DS4_MIN_CC = 70`); the older
  "EXL3 needs compute capability 8.0" rule was true only while the expert kernels were sm_80-only.

## How it was installed (this repo's record of it)

Maya's setup pins **LibertAIDAI**'s 2.9 bpw by repo/revision/sha256, so `--ds4-quant exl3` refuses this
Mia-AiLab build. It was packed by hand with the tree's own packer —
`.venv/bin/python tools/ds4/pack.py --model <dir>` — which validated `config.json` (`model_type:
deepseek_v41`, `quant_method: exl3`), indexed **192,503 tensors in 41 files** and wrote the Engram hash
tables, tokenizer and chat template into `<dir>/maya-ds4/`. The pack copies no weights.

Two things that cost time and are worth knowing: the Engram shards belong **inside** the model directory
(the pack indexes them as files 40 and 41), and `ds4.txt` records an **absolute `model_dir`**, so the file
was repointed to `/mnt/nvme/exl3-mia` after the set was copied to the NVMe.

## Method

Maya v1.1.53, `--max-context 131072 --eos 1 --vision off --tp 2 --prefill-chunk 16384 --cpu-threads 20
--dspark none`, arms differing only by `--suffix-draft 0` / `3`. Fresh load per measured run with a
discarded 100K/200-token burn first. `model-bench` 0.1.0, 400 tokens, temperature 0.5, fixed seed, depths
20K / 60K / 100K (150K+ skipped). The tokenizer used for slicing is the **same file** as the UD-IQ1_S
side, so both datasets slice identical prompts.
