## What is raw, what is derived

- **Raw** (`data/raw/`): the four model-bench run dirs as the harness wrote them (`results.jsonl`,
  `meta.json`, `summary.csv`), with `SHA256SUMS`. Unedited.
- **Derived** (`data/csv/`): `averages.csv` (2-run mean and per-run min/max), `means.csv` (the per-run
  rows the charts read), `facts.json`. Regenerated by `scripts/build_data.py`, which asserts 4 runs,
  12 arms and the same document at each depth across runs.
- **Charts** (`charts/`): `scripts/make_chart_depth.py` and `scripts/make_chart_compare.py`, both reading
  `data/csv/means.csv` (the comparison also reads the sibling UD-IQ1_S folder's copy). The comparison
  script prints the ratio from the CSV; no headline figure is typed.

## Which numbers these are

Maya **v1.1.53**, engine `maya-ds4` for sm_70, EXL3 decode through the legacy `v1.1.8` kernels
(`exl3: CUDA0/CUDA1 decodes with v1.1.8's kernels` in the engine log). Config in
`serving/maya-ds4-exl3mia-calibrated.json`; arms are that config with `--suffix-draft 0` or `3`.
Calibration (`installer.calibration`): `--tp 2` → **effective TP per GPU 2/2** (4.6 tok/s, 186 tok/s on a
15,671-token prompt) against `--tp 1` → 1/1 (4.1 tok/s, 129 tok/s); `--cpu-threads 20` kept; DSpark
drafter rejected, 3.32 against 4.96 tok/s.

Means of **2 runs per arm**, per-run spread in `data/csv/averages.csv`.

## Comparability with the UD-IQ1_S folder

Same box, same engine version, same context, same `--prefill-chunk` / `--cpu-threads`, same two arms, and
the **same tokenizer file** for prompt slicing, which the harness records as
`local tokenizer (exact, gguf UD-IQ1_S)` on both sides. `build_data.py` asserts the document per depth in
each folder; both folders slice `frankenstein` at 20K, `sherlock` at 60K and `pride` at 100K, so the
comparison is like-for-like at every depth.

## What could not be reached / what is not covered

- **The Engram tables could not be sha256-checked in the packing step** — `tools/ds4/pack.py` indexes them
  but does not hash them; the hashes above were verified independently at download time, before the set
  moved to the NVMe.
- **No as-shipped (uncalibrated) arm.** Both sides were measured at each model's own calibrated setting,
  which is what "fastest settings" means here — so the EXL3-vs-IQ1_S delta carries two different
  calibration outcomes (TP 2/2 vs 1/1) as part of each file's own optimum, not as a controlled variable.
- **One box, one engine version.** This says nothing about how the same checkpoint performs on Blackwell
  or on a box whose RAM holds the expert set; the CPU lane is the whole story here.
