# 01 — First bench: the new MiniCPM MoE on the V100s (2026-10-13)

## What was asked

Run the model-bench battery on `openbmb/MiniCPM-V-4.7-35B-A3B-gguf` (Q8_0 — the file Eamon
linked) on box .5, generate the graphic, queue the post.

## Setup facts (verified on-box)

- **Engine build**: llama.cpp `b11580` (`4413a1924`, 2026-10-12 master). This is the first master
  with MiniCPM-V 4.7 support — `model : support MiniCPM-V 4.7 (#29416)` (merged 2026-10-10) adds
  the `qwen35moe` text path (canvas M-RoPE) and the MiniCPM-V 4.7 mtmd vision path. Rebuilt from
  source for this box: CUDA 12.9.86, `CMAKE_CUDA_ARCHITECTURES=70` (sm_70-only), ccache;
  previous build (b11429) backed up to `~/llama-backup-b11429/`.
- **The fork question**: `tc-mb/llama.cpp-omni` (linked from the model card for LES) is the
  on-device omni engine — SSD expert streaming for phones, not needed when all weights fit VRAM.
  Mainline llama.cpp runs this model natively. No fork used.
- **Model**: `MiniCPM-V-4_7-35B-A3B-Q8_0.gguf`, 36,902,368,928 B, sha256 `8543ee5b…07d16b`
  (verified vs HF metadata). Vision projector `mmproj-model-f16.gguf`, 1,119,575,840 B (16x
  downsample default). Both live on `/mnt/models/MiniCPM-V-4.7/openbmb/` (HDD, permanently).
- **Architecture**: 40 layers, hybrid linear+full attention (full attention every 4th layer),
  256 experts / 8 active per token, 2 KV heads × head_dim 256 for the full-attention layers,
  ctx 262144, 733-tensor GGUF. **No nextn/MTP tensors in the file** — the MTP head was skipped at
  conversion, so there is no in-model drafter (the DSpark draft model is a separate release and
  was not tested; side-model tests are out of scope).
- **Serving** (stock flags — only placement/ctx explicit): `GGML_CUDA_ALLREDUCE=internal`
  (NCCL on this box is a CUDA-13 build on a CUDA-12.9 system — the first allreduce aborts without
  this, known from the Oct-5 Flash-Next sweep), `--ctx-size 262144 --n-gpu-layers 99
  --device CUDA0,CUDA1 --fit off --mmproj <f16> --jinja`, everything else binary defaults
  (`-b 2048`, `-ub 512`, f16 KV, flash-attention auto, split-mode layer). Exact argv:
  `data/raw/serve-command.txt`.
- **Load**: 8m52s from HDD (37 GB read), 4 slots, kv-unified, `n_ctx_slot = 262144`.
  VRAM at run time: 23.3 / 21.0 GB. Temps 37–43 °C across the battery (the 7k-rpm fan held it).
- **Strata was stopped for the run and restarted after** (the standing arrangement for GPU tests
  on .5) — `swift-1.5-q2_0` was serving again within ~2 minutes of the bench server coming down.

## Method

One bench run, six depths (20k / 60k / 100k / 150k / 200k / 250k), one unique document per depth
(frankenstein / sherlock / pride / tale2cities / greatexp / mobydick), prompts sliced to exact
token counts with the model's own GGUF tokenizer, 400 generated tokens per arm, temp 0.5, seed
12345, unique request tag (no cache reuse — `cache_prompt: false` on every request), one discarded
warm-up. Prefill/decode read from llama.cpp's own `timings`; the engine's per-request lines are in
`data/raw/llama-server-request-extracts.txt` (they match the CSV to the decimal).

One process note, for the record: the first attempt was aborted — the bench harness's backend
detector read the new llama.cpp `/v1/models` format (which now carries `architecture` on its
items) as "Strata" and sent the battery through the chat endpoint. The detector was fixed on the
box the same morning (`owned_by: llamacpp` is now checked first), the aborted run discarded
(directory renamed `-ABORTED-chat-endpoint-misdetect`), and the battery re-run on the canonical
`/completion` path. Only the clean run's numbers are in this dataset.

## What the numbers say

- **Decode is the story.** 87.5 → 57.3 tok/s across a 12.5× context range. That is the MoE shape
  doing exactly what it should on old VRAM-heavy cards: 36.9 GB of weights (Q8_0, all experts
  resident) but only ~3B active per token, so the compute per token stays small.
- **Prefill moves the same direction as every model on this box**: 754 → 431 tok/s (down 43% over
  the depth range), consistent with the ~1,000 → ~700 tok/s shape the serving engine shows on a
  much larger model.
- **A useful cross-batch point**: the Oct-5 llama.cpp sweep on the qwen4exp path (Flash-Next)
  measured ~109–113 tok/s prefill on this same rig. The `qwen35moe` path does 500–754 — the
  architecture branch, not the card, is what moved.
- **Vision is real on sm_70**: `STRATA VISION OK 417` + blue rectangle / green triangle / red
  circle, read exactly, 5.2 s wall for the whole request (361 prompt tokens incl. the image,
  decode ~92 tok/s on that run). `chat_template_kwargs {"enable_thinking": false}` needed, as
  usual for this family.
