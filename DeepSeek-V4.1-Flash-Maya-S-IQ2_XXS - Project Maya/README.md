# DeepSeek-V4.1-Flash-1017 (Maya-S IQ2_XXS) on Project Maya — the bench record on box .5

**2 recorded runs — 6 measured arms, all measured, 0 failed.** DeepSeek-V4.1-Flash-1017 served by
Project Maya **v1.1.19** (engine `maya-ds4`) on **2× Tesla V100 32 GB**, measured **2026-10-21** on
box .5. One GGUF set throughout: Maya-S IQ2_XXS, **339.5 GB** across six shards, layer-split across
both cards, **131,072 context**, no speculation. Every number came off a real run on this hardware;
nothing is estimated from a datasheet.

The findings that matter:

- **Prefill holds 144–153 tok/s across the three depths and peaks at 155.3 tok/s** at a 100K prompt
  (means 143.7 / 147.2 / 152.6 at 20K / 60K / 100K). It is flat with depth — 6% end to end.
- **Decode is the constraint: 5.5 / 6.3 / 7.3 tok/s** at the same depths, peak 8.7. Spread between
  the two loads is 0.2–4.7% on prefill but **27–48% on decode**, because `maya-ds4` re-times and
  re-plans its CPU/stream lanes on every load. The two-run mean is the published figure.
- **This is a memory-bound configuration, not a compute-bound one.** Both cards sit at ~31.9 of
  32 GB, and 10,709 of the 15,360 routed experts (117.8 GB) stay on the CPU lane and are read in
  place from NVMe and SATA per token.
- **No speculation**: the shipped DSpark drafter was downloaded and deliberately not used — Maya's
  own calibration measured 4.6 tok/s with drafting against 6.8 without at short context.
- Runs recorded: **2 — both measured, 0 failed.** All six arms completed 400 generated tokens and
  both runs sliced the same document at each depth. The 14:09Z burn battery is excluded by design
  (post-load cache warm-up).

## Model and layout on the box

- `peasantsmith/DeepSeek-V4.1-Flash-1017-Maya-GGUF`, `Maya-S/` — 6 shards, **339.5 GB** (experts
  IQ2_XXS/IQ2_S/IQ3_XXS/IQ3_S, 178.2 GB; Engram Q6_K 161.3 GB), plus an 8 GB DSpark drafter
  (downloaded, not used).
- Experts shards 1–4 on the SN730 NVMe (`/mnt/nvme/maya-ds4/Maya-S/`), Engram shards 5–6 on the
  boot SATA SSD (`/home/eamon/maya-ds4/engram/`, symlinked into the model dir). The whole set does
  not fit the 234 GiB NVMe; splitting keeps the per-token reads on NVMe and the engram rows on SATA.
- Pack is an index only (`tensors.txt` 3.7 MB, `engram.bin` 518 KB) — no weight copies.
- Engine: 10,709 of 15,360 routed experts on the CPU lane (117.8 GB read in place); VRAM
  31.9 / 32 GB per card. `--tp 2` is in the config but the engine reduces it to 1 on this quant —
  see the Maya-XS folder's write-up for the block-arithmetic reason and the source line.
- Unsloth's UD-IQ1_S set was downloaded and verified first, then deleted: the engine has no IQ1_S
  (ggml type 19) kernels — the packer refuses it. IQ2_XXS is the smallest quant Maya can read here.
