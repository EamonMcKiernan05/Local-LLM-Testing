# MiniMax-M3.1-Flash (Maya-S IQ2_XXS) on Project Maya — the bench record on box .5

**1 recorded run (3 measured arms), 0 failed.** peasantsmith **MiniMax-M3.1-Flash-Maya-GGUF**, quant
**Maya-S IQ2_XXS** — 3 shards, 122 GB decimal (116 GiB), 428B total / ~23B active — served by Project Maya
**v1.1.35** (`maya-mm3`, its own MiniMax arch) on **2× Tesla V100 32 GB**, measured **2026-10-28** on box
.5 at **131,072 context**, `--kv-streaming on --vision on --dspark off`, 200 generated tokens per depth.

**Verdict: it loads and it answers, and it is not a serving candidate on this box.**

| depth | prefill tok/s | decode tok/s |
|---|---:|---:|
| 5K | 19.2 | 1.9 |
| 20K | 19.4 | 1.8 |
| 60K | 19.2 | 0.8 |

- **Reading is ~19 tok/s and writing is 0.8–1.9 tok/s**, one to two orders of magnitude under the
  DeepSeek tier on the same cards.
- **The mechanism is residency**: only **2,849 of 7,296** routed experts fit in VRAM (39 %), so the CPU
  lane carries the rest and every decoded token pays for it. DeepSeek-V4.1 sets of similar size land at
  5–17 tok/s decode because a much larger fraction of their experts stays resident.
- **Decode falls off a cliff with depth** (1.9 → 1.8 → 0.8 tok/s), which is the KV streaming plus the
  expert lane, and it is the reason a 60K conversation is unusable here.
- One run only, one rep per depth: the shape is the finding, the exact figures are a single draw.

## Method

Maya v1.1.35, `maya-mm3`, 131,072 context, KV streaming on, vision on, drafter off. `model-bench` 0.1.0,
200 tokens per arm, exact local-tokenizer slices, temperature 1.0 / top_p 0.95, seed 12345, one rep per
depth at 5K / 20K / 60K.

## Note on the battery shape

This run used a 5K/20K/60K depth set and 200 generated tokens, not the 20K/60K/100K × 400 battery the
DeepSeek and GLM batches use — it was a first-contact test of a new architecture, not a like-for-like
sweep, and the card and CSV say so. Do not average these figures with another model's.
