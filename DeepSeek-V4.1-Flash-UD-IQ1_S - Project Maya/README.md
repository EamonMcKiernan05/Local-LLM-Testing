# DeepSeek-V4.1-Flash-1017 (unsloth UD-IQ1_S) on Project Maya — the bench record on box .5

**4 recorded runs (12 measured arms), 0 failed.** DeepSeek-V4.1-Flash-1017 served by Project Maya
**v1.1.53** (engine `maya-ds4`) on **2× Tesla V100 32 GB**, measured **2026-11-05** on box .5, from the
NVMe copy. One GGUF set: unsloth `UD-IQ1_S`, **284,640,120,584 bytes** — 123.4 GB of weights in shards
1–4, the 161.3 GB Q6_K Engram table sitting alone in shard 5, plus a 1 GB mmproj — at **131,072 context**.
Every number came off a real run on this hardware.

The findings that matter:

- **Prefill 513.8 / 727.5 / 689.2 tok/s** at 20K / 60K / 100K (2-run means, drafting off), **peak 738.0**;
  **decode 12.00 / 16.10 / 16.05 tok/s**, peak **17.1**. Prefill climbs steeply to 60K and plateaus.
- **Tensor parallel is refused on this quant on two GPUs.** The config asks for `--tp 2`; the engine logs
  `tensor parallel 2 -> 1` at every load because 2,304-wide expert planes do not halve into whole
  256-value IQ1_S blocks. Both cards work — one layer group each — and the calibration records
  `effective TP per GPU: 1/1` for both `--tp 2` and `--tp 1`.
- **The DSpark drafter loses here**: 9.16 tok/s with it against 11.18 without (618 of 896 drafts
  accepted), so Maya's own speed calibration kept `--dspark none` and the config ships that way.
- **Prompt-lookup drafting (`--suffix-draft 3`) is a wash**: +3.9 % prefill and +2.2 % decode at 100K,
  but +4.0 % prefill / −11.2 % decode at 20K and −1.0 % prefill / −19.9 % decode at 60K. Every one of
  those cells sits inside the ±15 % decode spread this engine shows between loads. It costs nothing, so it
  stays available; it is not a lever.
- **Residency, from the engine's own start log**: 6,448 of 15,360 routed experts in VRAM (42 %), the
  CPU lane carrying 8,918 experts — 67.1 GB read in place.
- **Against the archived 1 Nov v1.1.45 runs** on the same set and the same tuned config (drafting off):
  prefill **+10.8 % / +13.1 % / +2.8 %** at 20K/60K/100K (463.6 / 643.4 / 670.3 then); decode +14.3 % at
  20K, −1.0 % at 60K, +39.6 % at 100K — and that last one is not a clean delta, because the 1 Nov arm's
  three runs at 100K spanned 6.4–12.0 tok/s. The pair also spans two different days, so treat it as an
  update signal, not a controlled measurement.

## Layout

- `data/raw/` — the four model-bench run dirs (results.jsonl, meta.json, summary.csv), renamed to
  `<slug>-<arm>-run<n>`, with `SHA256SUMS`.
- `data/csv/` — `averages.csv` (means and per-run spread per arm per depth), `means.csv` (the per-run
  rows the charts read), `facts.json` (counts, harness metadata, run list).
- `scripts/` — `build_data.py` (raw → CSV/JSON, asserts 4 runs / 12 arms / same document at each depth)
  and `make_chart_depth.py` (+ `chartlib.py`).
- `serving/` — the as-benched Maya config and the post-calibration snapshots (the tuner rewrites the
  config: TP grouping, CPU threads, and the drafter verdict live in `installer.calibration` and
  `installer.speed_calibration`).
- `PROVENANCE.md` — what is raw, what is derived, and what could not be reached.

## Method

Maya v1.1.53, `--max-context 131072 --eos 1 --vision off --tp 2 --prefill-chunk 16384
--cpu-threads 20 --dspark none`, arms differing only by `--suffix-draft 0` / `3`. Every measured run had
its own fresh load and a discarded 100K/200-token burn first. `model-bench` 0.1.0, 400 tokens generated,
temperature 0.5, fixed seed, one rep per depth, depths 20K / 60K / 100K (150K+ skipped — context is
131,072). Two runs per arm; means published, per-run spread in `data/csv/averages.csv`.

Calibration, Maya's own tuner, the night before (config in `serving/`): `--tp 2` and `--tp 1` produce the
same effective grouping so they were not compared, `--cpu-threads 20` beat the engine's own 14 and 10
(10 threads: 7.9 against 9.9 tok/s), and the DSpark drafter was measured and rejected.
